# Milestone 2：通用控件与事件

## 目标与模块边界

计数器与交互式表单使用同一个 Screen、Parser、Serializer 和 EventBus。应用提供初始文档、协议校验和同步纯处理器；核心不包含计数器、表单或字段名称的判断。

Screen 的基础 API 仍是 `setContent`、`onChange`、`getContent`。`start` / `close` 负责监听器的生命周期。EventBus 独立订阅 Screen，按稳定 ID 派发控件变化。

## 控件协议

每个受管理控件紧接一个隐藏 HTML 注释，声明稳定 ID 和类型。ID 在单份文档内唯一，允许字母、数字、下划线、点和连字符。标签和行号不参与身份判断。移动整段控件时需要带上注释；复制控件时需要分配新 ID。

| 类型 | 示例 | 语义 |
|---|---|---|
| check | `- [x] Enable sound <!-- textui:id=sound type=check -->` | 持久布尔状态 |
| action | `- [ ] Submit <!-- textui:id=submit-main type=action -->` | 未选中到选中触发一次操作 |
| input | `> Name: [June] <!-- textui:id=name type=input -->` | 持久字符串 |
| select | `(*) Dark <!-- textui:id=dark type=select group=theme -->` | 分组选择 |
| output | `Count: 12 <!-- textui:id=count type=output -->` | 应用输出；不派发用户操作事件 |

同行也可放置多个控件，但每个控件都要有自己的注释。input 用 `\\`、`\]`、`\n`、`\r` 表示反斜杠、右方括号和换行。output 为单行文本。只有带有控件注释的区域参与控件解析；普通 Markdown、备注和未标记的复选框保持原样。

`serialize(parse(text))` 无更新时逐字返回原文。更新按原文位置从后向前替换控件值，保留标签、注释、其他文本、换行和结尾空白。Screen 更新版本注释属于另外一个受管理区域。

协议标记损坏、重复 ID、控件类型变化或同一分组同时新选多个选项时，整批业务不执行并报告错误。修复后从上次有效文档继续比较。新增勾选状态的 action 被拒绝，避免控件插入就执行业务。

## 事件与操作确认

一份保存生成一批事件，按控件在文档中的顺序排列。处理器同时看到最新字段值，因此修改 Name 并勾选 Submit 的同次保存会使用新 Name。选中某个 select 后，同组其他选项自动取消；允许全部取消，表单结果显示 `theme=none`。

action 只在未勾选到勾选时触发。业务处理器返回更新后，EventBus 将输出、选择归一和 action 复位合并提交。处理器抛错时不确认操作；不能把网络调用等不可逆副作用放进这一阶段的处理器。

持久字段与输出从文件恢复；重启不会重放启动时已有的 action 勾选，而是复位它们。这样避免把上次遗留的操作视作新请求，代价是未确认操作不会在启动时自动重试。

## 回环与重复保存

Screen 比较实际完整内容，不根据 epoch 相等跳过不同内容。自己的写入更新内存快照，后续监听回声被忽略。`setContent` 回写前再次比较磁盘原文；不一致时放弃旧快照，等待下一次保存处理。

EventBus 记录当前进程最近 128 个成功 action 请求的 SHA-256。编辑器重存完全相同的原请求时，恢复当前已确认输出并复位操作，不再派发业务事件。编辑器加载回写后发起的新操作具有新的文档版本，可以正常执行。

这是本地单进程的重复保存保护，不是跨进程、进程崩溃或网络请求的 exactly-once 保证。一个文件只应由一个 CLI 实例驱动。当前使用同步文件 IO；原文比较不能提供与外部编辑器跨进程的原子比较并交换。多人协作、网络幂等键和持久操作日志留待后续阶段。

## 验收：8/8 自动化通过

- [x] 计数器和表单共用同一个核心引擎，并覆盖同行控件。
- [x] 两个同名控件具有独立 ID，移动行和修改标签后身份稳定。
- [x] 修改多个控件正确派发多个事件，提交读取本次保存的新值。
- [x] 重复保存确认文档及原请求不重复执行，新请求仍可执行。
- [x] 引擎回写不产生事件回环，相同 epoch 的外部修改正常处理。
- [x] 保留普通文本、额外控件、CRLF 与结尾空白。
- [x] 重启恢复持久状态，启动不重放遗留 action。
- [x] 外部普通保存和原子替换后继续检测后续修改。

验收代码在 `tests/engine.test.ts`，另含损坏协议恢复测试。测试使用真实文件监听与临时目录，不依赖模拟监听器；CLI 的真实子进程测试覆盖计数器和表单。特定编辑器的任务列表点击、自动保存和预览刷新尚需在该编辑器中验证。

## CLI 应用注册

所有界面与示例文件统一使用 `.md`。CLI 的应用列表集中在 `src/apps/registry.ts`，每条记录仅含 ID 和 Application；默认文件名为 `<id>.md`。不带参数运行全部注册应用，指定 ID 时只运行该应用，可以另传 `.md` 路径。

`cli-options.ts` 负责参数与帮助信息，`runtime.ts` 负责通用启动、校验与释放。CLI 本身只编排这些模块，添加应用不需要增加应用专属条件分支。

本里程碑完成后具备扩展字符网格应用的模块基础；本次没有实现 Grid Widget 或棋盘业务。
